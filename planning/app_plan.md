# 뿡뿡이 — 커플 추억 아카이빙 앱 기획

## 1. 한 줄 정의

우리 둘이 함께한 순간을 사진과 함께 쌓아두고, **시간(타임라인)**과 **공간(지도)** 두 가지 방식으로 다시 볼 수 있는 웹앱.

## 2. 방향성

- 목적은 "우리 둘이 실제로 쓰는 앱"이지 서비스 출시가 아니다. 사용자는 2명으로 고정.
- 기록 자체보다 **다시 보는 경험**이 중요하다. 입력은 최대한 짧게, 보는 화면은 예쁘게.
- 톤은 귀엽고 아기자기하게. 파스텔 컬러, 둥근 모서리, 손글씨 느낌 포인트 폰트.
- 웹앱으로 만든다. 아이폰 앱스토어 심사를 피하고, PWA로 홈 화면에 추가하면 앱처럼 쓸 수 있다.

## 3. v1 범위

들어가는 것:

1. **공유 타임라인** — 사진 + 짧은 글을 날짜순으로 쌓는 피드
2. **지도 아카이브** — 사진에 붙은 위치로 전국/서울 지도가 채워지는 기능 (핵심 차별점)
3. **D-day / 기념일** — 사귄 날부터 며칠째, 다가오는 기념일 카운트다운
4. **커플 페어링** — 초대코드로 둘을 연결

빼는 것 (v2 이후 후보):

- 채팅 / 실시간 메시지 (카톡이 이미 있음)
- 미션·챌린지, 포인트 시스템
- 무드 체크인
- 푸시 알림 (iOS 웹 푸시는 PWA 설치 필수 + 설정이 까다로워서 v1에서는 제외)

## 4. 화면 구조

하단 탭 5개 기준.

```
┌─────────────────────────────────────────┐
│  홈    타임라인   [ + ]   지도    설정   │
└─────────────────────────────────────────┘
```

### 4.1 홈

- 상단에 D-day 크게 (사귄 지 N일째)
- 다가오는 기념일 1~2개 (D-7 이런 식)
- 최근 추억 3~4개 썸네일
- 지도 채움 진행률 요약 ("전국 18곳 · 서울 12개 구")

### 4.2 타임라인

- 날짜 역순 피드. 사진, 글, 장소 이름, 작성자 표시
- 월별 구분선
- 무한 스크롤 (페이지네이션)

### 4.3 지도

- 전국 뷰 / 서울 뷰 토글
- 다녀온 지역은 파스텔 색으로 채워지고, 안 간 곳은 연한 회색
- 진행률 표시 ("229개 중 18곳")
- 지역을 누르면 그 지역에서 찍은 추억 목록이 뜸

### 4.4 기록하기 (+)

입력 단계를 최대한 짧게:

1. 사진 선택 (여러 장 가능)
2. 날짜 자동 추출 → 수정 가능
3. 위치 자동 추출 → 없거나 틀리면 직접 선택
4. 한 줄 글
5. 저장

### 4.5 설정

- 사귄 날 설정
- 기념일 추가 / 수정
- 파트너 초대 (초대코드 발급)
- 프로필 (이름, 사진)

### 4.6 온보딩

로그인 → 커플 만들기 or 초대코드 입력 → 사귄 날 설정 → 홈

로그인은 Google 로그인 하나만. (Supabase는 카카오 로그인도 기본으로 지원하니 나중에 쉽게 추가할 수 있다)

## 5. 데이터 모델 (Postgres)

전체 정의는 [`supabase/schema.sql`](../supabase/schema.sql) 에 있다. 요약하면 네 개의 테이블.

```
couples        id, invite_code, start_date
profiles       id(=auth.users), display_name, photo_url, couple_id
posts          id, couple_id, author_id, body, photos(jsonb), taken_at,
               lat, lng, place_name, region_code, region_sido,
               region_sido_short, region_sigungu, location_source
anniversaries  id, couple_id, title, date, repeat_yearly, emoji
```

커플 소속은 `profiles.couple_id` 에만 있다. 커플 쪽에 멤버 목록을 따로 들고 있으면
두 곳이 어긋날 수 있어서 한쪽에만 둔다.

**다녀온 지역은 테이블이 아니라 뷰다.**

```sql
create view visited_regions as
select couple_id, region_code, count(*), min(taken_at), max(taken_at)
from posts where region_code is not null
group by couple_id, region_code;
```

글에서 바로 계산하므로 따로 유지할 카운터가 없고, 원본과 어긋날 일도 없다.

Storage 경로: `photos/{couple_id}/{post_id}/{n}.jpg` (비공개 버킷, 읽을 때 서명된 주소 발급)

접근 통제: RLS 로 모든 테이블이 기본 차단이고, `couple_id = my_couple_id()` 일 때만 통과.

## 6. 지도 기능 상세

이 앱의 핵심이라 따로 정리.

### 6.1 렌더링 방식

카카오맵/구글맵 같은 실제 지도 타일은 쓰지 않는다. 아기자기한 톤과 안 맞고, "채워진다"는 느낌도 안 산다.

대신 **GeoJSON 행정구역 경계를 SVG로 직접 그린다.** 색칠공부 스티커 같은 느낌이 나고, 색·모양을 완전히 제어할 수 있고, 훨씬 가볍다.

- 데이터: 대한민국 행정구역 GeoJSON (시도 / 시군구 레벨 공개 데이터 존재)
- 원본은 용량이 커서 mapshaper 같은 도구로 단순화해서 사용
- 전국 뷰는 **시군구 레벨(229개)** 기준. 시도 17개는 너무 빨리 다 채워져서 재미가 없다
- 서울 뷰는 **자치구 25개** 기준으로 확대

### 6.2 사진 → 지역 판정

좌표를 행정구역으로 바꾸는 걸 외부 API 없이 처리할 수 있다. 지도를 그리려면 어차피 GeoJSON 폴리곤이 있어야 하니, **같은 데이터에 점-다각형 포함 판정(point-in-polygon)**을 돌리면 된다. API 키도, 호출 제한도 없다.

### 6.3 위치를 얻는 방법

사진 EXIF에서 GPS를 읽는다 (`exifr` 같은 라이브러리로 브라우저에서 가능).

**다만 이게 생각보다 자주 실패한다:**

- 카카오톡으로 주고받은 사진은 EXIF가 지워져 있다
- 스크린샷에는 위치가 없다
- 아이폰 HEIC 포맷은 브라우저/설정에 따라 처리가 달라진다
- 사진 촬영 시 위치 권한이 꺼져 있었으면 애초에 없다

그래서 **자동 추출은 보조 수단으로 두고, 직접 장소를 고르는 경로를 기본으로 갖춰야 한다.** 자동으로 잡히면 "여기 맞아?"로 확인만 받는 식.

장소를 직접 고를 때는 지도에서 핀을 찍는 것보다, 장소 이름을 검색해서 고르는 게 훨씬 편하다. 이 부분은 카카오 로컬 API를 쓰면 깔끔하다 (무료, 한국 장소 데이터).

### 6.4 재미 요소

- 새로운 지역을 처음 채웠을 때 축하 연출
- 진행률 ("전국 229곳 중 18곳 · 7.9%")
- 지역별 첫 방문 날짜

## 7. 기술 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js | 익숙함, Vercel 배포가 자동 |
| 배포 | Vercel | 이미 해본 조합, 설정 거의 없음 |
| 인증 | Supabase Auth (Google) | DB와 같은 프로젝트, RLS와 바로 연결됨 |
| DB | Supabase (Postgres) | 지도 집계가 SQL 한 줄, 무료 플랜에 카드 불필요 |
| 사진 저장 | Supabase Storage | 같은 프로젝트, 무료 1GB |
| 스타일 | Tailwind CSS | 빠른 반복 |
| 지도 | GeoJSON + SVG 직접 렌더 | 톤에 맞고 의존성 없음 |
| 앱처럼 쓰기 | PWA (홈 화면 추가) | 스토어 심사 회피 |

처음엔 Firebase로 만들었다가 Supabase로 옮겼다. 이유는 세 가지.

1. 이 앱의 핵심인 지도 집계가 SQL의 `group by` 한 줄인데, Firestore는 집계를 못 해서
   카운터를 손으로 유지하는 코드가 필요했다
2. Firebase는 사진 저장에 카드 등록(종량제 전환)이 필요하다
3. Postgres 지식은 다른 곳에서도 쓰인다

옮길 때 실제로 바뀐 건 `lib/` 안쪽뿐이고 화면 코드는 거의 그대로였다.
DB 호출을 `lib/db.ts` 한 곳에 모아둔 덕분이다. 앞으로도 이 규칙은 지킨다.

## 8. 구현 순서

1. Next.js 프로젝트 + Supabase 연결 + Google 로그인
2. 커플 생성 / 초대코드 페어링
3. 글 작성 (사진 업로드 + 글) → 타임라인 표시
4. D-day / 기념일
5. 지도 (GeoJSON 렌더 → 지역 판정 → 채우기)
6. 디자인 다듬기, PWA 설정
7. 배포하고 실제로 써보기

각 단계마다 실제로 동작하는 상태를 유지한다. 3번까지만 돼도 앱으로서 쓸모가 있다.

## 9. 비용

2명 사용 기준이면 Supabase 무료 플랜(DB 500MB, 사진 1GB) 안에서 다 해결된다. 카드 등록도 필요 없다.
업로드할 때 이미지를 줄여서 저장하므로 사진 용량도 한참 버틴다.

한 가지, 무료 프로젝트는 일주일 넘게 안 쓰면 잠시 멈춘다. 대시보드에서 다시 켜면 된다.
